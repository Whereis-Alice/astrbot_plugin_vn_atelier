# 每日精选、今日清单与今日新作

[返回首页](../README.md) · [配置指南](configuration.md) · [数据来源](data-sources.md)

三个栏目**分别发图、分别发送消息**，不会把清单或新作拼进精选卡。共用推送时间和订阅会话，可以各自开关。

## 会收到哪些内容

| 栏目 | 默认 | 展示方式 |
| --- | --- | --- |
| 每日精选 | 开 | 一张精选发售纪念卡、一张精选生日卡；有对应内容才发送 |
| 今日清单 | 关 | 另发一张图，分为作品发布纪念日、其他角色生日两栏 |
| 今日新作 | 关 | 再单独发一张长图，逐部展示当天首发作品的资料与简介 |

全部开启且都有结果时，每次最多发送四条独立图片消息。某个栏目查询或出图失败不会取消其他栏目；没有结果的栏目不会发空图。自动推送出图失败会跳过该栏并记录日志，手动查询则可按设置退回文字。

## 每日精选：继续挑一部，也不漏掉同作寿星

- 纪念日作品继续按「选取作品的口味」挑选：评分优先、热度优先，或评分优先并排除票数过少的作品。
- 精选生日先从 VNDB 当日生日候选中，按关联作品挑出精选，再查询**这部作品所有同日生日的角色**。
- 只有一位寿星时继续用单人卡；同作多位寿星时放在同一张精选生日卡，一起展示，附上登场作品与作品评分。
- 同作补齐时不再按性别、戏份或作品评分删人。性别和质量设置只参与前面的精选候选筛选；性别无匹配时沿用不限性别的候选。

精选候选池最多 40 位，因此它是一个推荐栏目，不是当天所有角色的完整排名。

## 今日清单：快速看今天有哪些纪念日与生日

### 作品发布纪念日

查询配置的回溯起始年份至去年，**历年同月同日首次发售**的视觉小说。展示封面、作品名、发布年份与周年数、可取得的平台和开发信息，以及分来源的评分。按 VNDB 评分降序取最多 N 部，不设最低评分。

当年今日首发不算「0 周年」，交给今日新作栏目。2 月 29 日只查询存在该日期的年份。

### 其他角色生日

展示角色姓名、原名或别称、生日、可取得且已开启的角色资料、来源作品名称与 VNDB ID，以及一张小人设图。**这里不放作品简介或作品评分**，避免信息太挤。

生日名单仍由 VNDB 按月日查询，不限制角色性别、戏份或关联作品评分。先排除本次已成功生成精选生日卡的寿星，再取最多 N 位；没有精选生日卡时照常列出生日名单。按 VNDB ID 排序，顺序不代表人气。

### 数量与手动查看

- 「清单作品数上限」「清单生日角色数上限」默认**各 12**，可分别设为 1–50。
- 一张图列出，不分页；限制的是展示数量，不是当天总人数或作品总数。
- 手动发送 `工房 简讯` 查看同样的清单；`工房 简讯 06-24` 查看指定月日。手动查询不会排除精选寿星，也不受定时清单开关影响。

## 今日新作：只看今日首发的视觉小说

### 名单为什么来自 VNDB

使用 VNDB **作品条目的首次发售日期**精确匹配今天，而不是按条目入库时间，也不是从所有游戏中猜哪些是 Galgame。移植、翻译、补丁等发行记录不作为这份新作名单的独立来源。

Bangumi 游戏分类包含非视觉小说，适合作为资料与评分优先来源，不直接拿全游戏的当日发售结果充当 Galgame 新作。可取得的信息包括：

- 封面、中文名与原名、VNDB 首发日期；Bangumi 日期不同时另行标注；
- Bangumi 评分、评价人数、游戏排名，以及可取得的 VNDB 评分；
- 平台、开发、发行、类型及可取得的剧本、原画、音乐等制作信息；
- 简介（最多 600 字）、数据来源 ID 和条目链接。

**新作不设最低分或最低评价人数**。尚无有效评分显示「暂无」，不记成 0 分；中文资料关联失败时仍展示 VNDB 原资料。按 VNDB 评价人数降序取最多 N 部，默认 12，可设为 1–50。

手动发送 `工房 新作` 可预览，不必先开启定时新作推送。查不到条目不等于今天一定没有新作。

### 日期不代表已确认上架

两站资料由社区维护，可能更新较慢、遗漏条目，或保留尚未兑现的发行计划。推送只表示「数据源把首次发售日期记为今天」，**不是已确认上架通知**；请以发行方公告为准。

只知道年份、月份、待定或未收录日期的作品不会命中某个具体日期。早上推送时，也可能尚未录入当天的新作；可稍后手动查询，或自行调整推送时间。

## Bangumi 如何补充资料

作品沿用外链优先、精确标题／别名及年份核对的保守规则。多个候选、链接冲突或请求失败时不强行关联，保留 VNDB 名称与资料。两站评分保留 10 分制和 100 分制，不混算。

角色只在**已可靠关联的来源作品**内核对精确姓名或别名，且检查两边已知生日是否冲突；唯一候选通过后才补中文名和人设图。不会全站模糊搜索一个同名角色就直接套用。没有可靠结果时继续使用 VNDB 角色信息。

生日栏目只补角色资料与来源作品名；作品评分留在作品栏目和精选生日的附属作品区。补充数据受 Bangumi 开关、内容权限、缓存与接口可用性影响，不保证每条都有中文资料。

未开启成人内容时，新增清单、新作及寿星卡的 VNDB 备用图只使用明确未标记性内容的图片；标记缺失或有性内容标记时使用占位图。这只控制备用图片，不代表作品一定全年龄，第三方标记也不能视为绝对安全保证。

## 开启方式

1. 在插件配置的「每日推送」里，按需开启「推送今日清单」「推送今日新作」，设置数量并保存，重载 Gal工房。
2. AstrBot 管理员在目标会话发送 `工房 推送 开启`，或配置推送白名单。
3. 发送 `工房 推送` 查看订阅与栏目状态；先用 `工房 简讯`、`工房 新作` 检查内容和版式。

开关控制所有推送目标的栏目，不是每个群单独一份栏目设置；订阅和白名单仍沿用原有配置。取消某个栏目无需退订整个会话。

配置文件片段（请合并，不要覆盖原配置）：

```json
{
  "scheduleSetting": {
    "enableFeatured": true,
    "enableCalendar": true,
    "anniversaryCount": 12,
    "birthdayCount": 12,
    "enableNewReleases": true,
    "newReleaseCount": 12
  }
}
```

推送时间和「今天」按 **AstrBot 进程所在时区**计算。Docker 部署应同时检查容器时区。调到 50 条会生成更长、更大的图片，可能超过平台图片限制或渲染服务容量；建议先用默认值。

无需安装新的常驻服务。资料补充限并发、使用有界内存缓存；图片沿用现有磁盘缓存。数量越多，请求和渲染开销越大。评分是查询时可取得的缓存数据，不是实时更新通知，也不会在当天稍后自动补发一轮。

## 没收到某个栏目时怎么看日志

日志级别需保留 INFO。搜索 `[Gal工房]` 可以按顺序看到：

1. **配置已加载**：当前推送时间、三个栏目的实际开关与数量上限。保存配置后需重载插件，`工房 推送` 也能查看已加载的栏目。
2. **每日推送开始**：本轮查询日期、服务器时间及其时区偏移、栏目开关。
3. **今日新作查询**：VNDB 首发日期、展示上限、返回数量。0 部会明确说明跳过卡片，不会被当成请求失败；网络或返回结构错误会记录异常。
4. **图片已生成／未生成**：生成成功有编号和耗时，但此时尚未发送。查询或出图失败记录警告，仍继续构建其他栏目。
5. **分发与送达**：构建结束后才开始逐图发送。发送失败包含目标会话和图片编号，可与生成日志核对；没有订阅目标则直接记录跳过，不查询内容。

例如，看到 `今日新作：VNDB 首发日期=YYYY-MM-DD 返回 0 部，跳过新作卡片`（日期会替换为实际查询日），表示该次查询正常但没有匹配条目，不是定时器漏掉了新作栏目。

新作当前能查到，不代表早上定时查询时也能查到。空结果不发空图，不自动补发，也不改查往日作品。更多排查步骤见[常见问题](faq.md#开启了今日新作其他栏目都收到却没有新作也没报错)。
