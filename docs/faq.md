# 常见问题

[返回首页](../README.md) · [指令说明](usage.md) · [配置指南](configuration.md) · [LLM 工具](llm-tools.md)

先在 AstrBot 日志中搜索 `[Gal工房]`。反馈问题时请注明指令、现象和相关日志，并隐藏令牌、Cookie、代理密码及 Worker 口令。

## 只收到纯文本，图片发不出来

图片渲染走的是 AstrBot 自带的截图服务，插件只是把 HTML 交给它。收到纯文本说明渲染这一步失败了，兜底逻辑生效了。
到 AstrBot 日志里搜 `[Gal工房]` 看具体原因，最常见的是宿主机不能访问截图服务，或者一次要渲染的封面太多导致超时 —— 后者可以把「每个厂商展示的作品数」「榜单展示条数」调小。

## 图里的中文变成方框，或者字体很难看

默认用的是 CDN 上的霞鹜文楷。如果渲染环境访问不了 jsDelivr，就会退回系统字体；而很多 Linux 容器里根本没装中文字体，于是全成了方框。
两种解法：把「在线字体 CSS 地址」换成一个能访问的镜像；或者把「字体来源」改成系统字体，再把「字体名称」填成宿主机上确实装了的字体
（Windows 是 `Microsoft YaHei`，Linux 上常见 `Noto Sans CJK SC`；容器里可以先 `apt install fonts-noto-cjk`）。

## 下载查不到资源或出现 403

TouchGal 有 Cloudflare 防护，但 HTTP 403 也可能与权限或站点策略有关。先到日志里搜 `[Gal工房]`，区分以下情况：

**一、只是被客户端指纹拦下** —— 日志出现「转用浏览器指纹重试」，之后请求正常。

站点可能拒绝「看起来不像浏览器」的请求。插件收到 403 后会自动换用 `curl_cffi` 模拟真实浏览器的 TLS 指纹重试一次。
确认插件依赖 `curl_cffi` 已安装；即使重试成功，也不能仅凭这一点确认原始 403 的原因。如果仍失败，不要连续刷请求，继续检查响应是否包含浏览器验证提示。

**二、站点开启了浏览器验证** —— 日志出现「开启了浏览器验证」。仅模拟 TLS 指纹不能完成这类验证，处理方式见下一节。

另外，要看需要登录才可见的资源（含 R18）得填 Token：浏览器登录 [TouchGal](https://www.touchgal.ink/) 后，
从 Cookie 里复制 `kun-galgame-patch-moe-token` 的值，粘到「TouchGal 登录 Token」。
站点日后换域名也不用等插件更新，把新地址填进「TouchGal 站点地址」即可。

## 站点开启浏览器验证怎么办

日志出现「开启了浏览器验证」、响应头带 `cf-mitigated: challenge`，或正文是 `Just a moment...` 页面，表示站点要求浏览器验证。普通重试通常无法解决。出口 IP、客户端环境、请求行为和站点策略都可能影响结果，不能只凭 403 确定是哪一项。

**换服务器后，先核对当前实例的配置。** 部署 Worker 不会自动改掉「TouchGal 站点地址」。如果日志仍指向 `www.touchgal.ink`，说明目标站点没有切换为 Worker（仍可能经过配置的代理）；要使用自己已经部署的 Worker，需要填入它的完整地址（含访问口令路径），并建议把「单次请求超时」设为 60 秒。不要公开包含口令的地址。

可选配置及限制：

| 方式 | 适用情况与限制 |
| --- | --- |
| 已有代理 | 在「代理地址」填写自己管理且可正常访问站点的代理；是否可用以服务器实际请求为准。 |
| 已有 Browser Rendering Worker | 部署与配置见 [可选 Worker 组件](../extras/cf-worker-relay/)。浏览器运行在 Cloudflare，服务器不需要额外运行 Chrome。受免费额度、冷启动及站点策略限制，不保证长期可用。 |
| FlareSolverr | 在「浏览器验证求解服务」填自己管理的服务地址；浏览器占用额外内存，凭证仍可能失效。它不是唯一方案，也不保证通过所有验证。 |
| 手填 `cf_clearance` | 仅作临时凭证。尽量保持取值时的出口和浏览器 UA；迁移后旧值可能失效，反复粘贴同一值没有帮助。 |

**手填 Cookie 的注意事项：** 只填值本身；不要带 `cf_clearance=` 前缀或整段 Cookie（误填时插件会尝试截取）。「浏览器 User-Agent」填取值浏览器的 UA。没有填 UA 只表示无法确认一致性，并不等于已证实 UA 不匹配。日志里的签发时间是根据 Cookie 格式推测的，不能据此判断确切有效期；已经请求失败的旧值可以清空。

**普通反代不保证通过验证。** 把请求转发给 Worker 或 nginx，不等于上游站点会放行。Browser Rendering 也受站点策略限制，需要在实际部署环境中验证。

**先核对 Cloudflare 额度。** 浏览器启动、执行和保活等待都可能占用资源。免费额度与限制以 [Cloudflare 官方文档](https://developers.cloudflare.com/browser-rendering/platform/limits/)为准，不要按固定的「每天查询次数」估算。

插件命中验证后会对该站点冷却 300 秒，避免短时间刷屏。`工房 随机` 会尝试 VNDB 兜底；每日简讯获取 TouchGal 简介失败时，仍会尝试输出其余内容。`工房 下载` 依赖 TouchGal，必须恢复该来源才能正常获取资源。

## 图片不够清晰怎么调

「清晰度」调的是渲染时的设备像素比，相当于给渲染页面换一块高分屏：版式一模一样，但字和封面的实际像素更多。
卡片的排版宽度固定是 1000 CSS 像素，所以输出宽度就是 1000 乘以倍率；高度随内容长短变化。

| 清晰度 | 输出宽度 | 适合场景 |
| --- | --- | --- |
| 标准（1x） | 1000 px | 优先减小体积 |
| 高清（1.3x，默认） | 1300 px | 日常聊天 |
| 超清（1.8x） | 1800 px | 放大阅读小字 |

图片体积还取决于内容长度、封面数量、格式和压缩质量，不能仅凭清晰度档位保证文件大小。

日常用默认的高清就够 —— 聊天平台大多会对图片再压一次，清晰度的收益主要体现在放大看小字的时候。
觉得字发虚、或者想截图存档，调到超清。

「图片格式」建议保持 JPEG。PNG 是无损的，通常体积更大，部分平台会二次压缩甚至直接拒收大图，
除非确实要留无损存档，否则不划算。「图片质量」默认 95，是画质与体积的平衡点，过低可能使文字边缘出现压缩噪点。

如果宿主的截图服务版本较老、不认这些参数，插件会自动用一套保守参数重渲一次，并在日志里留一条警告 ——
如果兼容重试成功，清晰度会回到标准水平；仍失败时按配置退回文字回复。

## 每日简讯没有推

按顺序检查：

1. 推送时间的格式必须是 `HH:MM`；
2. 目标群里执行过 `工房 推送 开启`，或者配置里的推送白名单填了 `平台id-群聊id`；
3. AstrBot 的定时任务模块在你的部署形态下可用 —— 取不到时插件会跳过定时功能，并在启动日志里说明。
4. `工房 推送` 中显示了想接收的栏目。清单、新作默认关闭，需要在配置中单独开启；没有结果不发空图。

精选、清单、新作分别发消息，数量与日期来源见[每日推送说明](daily-push.md)。

## 有的作品查不到，或者搜出来的名字对不上

`工房 作品` 默认搜索 Bangumi 游戏，没结果或查询失败时回退 VNDB。可以尝试中文名、日文原名或罗马音；已知条目时，`工房 BGM 13` 或 `工房 ID v17` 分别精确查询两个来源。两站对本体、移植版与续作的划分可能不同，没有关联评分并不表示插件漏了评分字段。

## 能和原来的 astrbot_plugin_galgame_box 一起装吗

可以。插件名、指令与别名、数据目录、定时任务名、配置分组全部是独立的，两个插件同时启用不会互相覆盖。
唯一要注意的是它们都会向 VNDB 和 TouchGal 发请求，别在同一个群里同时刷。

## R18 内容怎么处理

默认关闭「允许 R18 内容」，插件按数据源提供的标记过滤成人条目和图片；第三方标记可能不完整，请勿将其视为绝对保证。开启前请自行确认所在群聊与平台允许此类内容 —— 这部分风险由部署者承担。

## 开了 LLM 工具但模型没有调用

参照 [LLM 工具指南的排查步骤](llm-tools.md#模型没有调用怎么办)，先确认工具已注册、当前人格允许使用，以及模型支持工具调用。工具默认只返回文字给模型，不会自动发送卡片。
