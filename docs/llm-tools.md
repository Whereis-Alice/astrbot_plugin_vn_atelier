# LLM 工具指南

[返回首页](../README.md) · [配置指南](configuration.md) · [指令说明](usage.md)

开启后，聊天模型可以调用 Gal工房查资料，再根据查询结果回答你。不必记住指令，也不需要部署 MCP 服务。

**工具默认关闭，只读资料，不操作收藏、不修改配置，也不自动发图片卡片。** 仍可照常使用 `工房` 指令，两种用法互不替代。

## 怎样开启

1. 打开 AstrBot WebUI → 插件管理 → Gal工房 → 配置。
2. 在「限流与扩展」中打开「开放给大模型调用」。
3. 保存配置，重载 Gal工房。无需重启整个 AstrBot。
4. 确认当前模型支持工具调用（Function Calling），且当前人格或会话的工具配置允许使用下方四个工具；若未设置筛选则无需另建白名单。

插件初始化成功后，日志会出现：

```text
[Gal工房] 已注册 4 个 LLM 工具
```

仅打开本插件开关，不保证模型每次都会调用。是否调用还取决于提问方式、当前模型和 AstrBot 的工具配置。

手动编辑配置时，开关是 `limitSetting.enableLlmTools`：

```json
{
  "limitSetting": {
    "enableLlmTools": true
  }
}
```

这只是配置片段，请合并到原有配置，不要覆盖整份文件。关闭开关后也需保存并重载，工具才会注销。

## 可以怎样问

正常触发机器人的聊天对话后，可以说：

- 「查一下 CLANNAD 游戏在 Bangumi 上的评分、评价人数和发售日，附来源链接。」
- 「看看 [Bangumi 条目 13](https://bgm.tv/subject/13) 的游戏资料。」
- 「帮我找找古河渚在 VNDB 的角色资料。」
- 「查一下 Key 这家会社有哪些代表作。」

这些是提问示例，不是固定口令。关键词搜索有多个结果时，请先确认具体作品，尤其注意同名动画、续作和不同平台版本。

## 四个工具

| 工具名称 | 适合做什么 | 数据来源 |
| --- | --- | --- |
| `vn_atelier_search_vn` | 按作品名查基本资料 | 优先 Bangumi，无结果或查询失败时回退 VNDB |
| `vn_atelier_search_bangumi` | 明确查询 Bangumi 游戏评分与制作数据 | 仅 Bangumi 游戏条目 |
| `vn_atelier_search_character` | 按角色名查资料和出场作品 | VNDB |
| `vn_atelier_search_producer` | 按会社或社团名查资料、代表作 | VNDB |

### 通用参数和返回值

四个工具都只有一个必填参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `keyword` | 字符串 | 作品名、角色名或会社名；Bangumi 专用工具还接受条目 ID 或链接 |

- 返回的是供模型阅读的**纯文本**，不是图片或固定格式 JSON。
- 每次最多返回 3 个结果，总文字最多约 1200 字符，超出会截断，因此不是完整档案导出。
- 字段随原站数据而定；缺少评分、发售日或制作人员时，不保证每项都有内容。
- Bangumi 无结果时返回「没有找到匹配的条目。」；VNDB 无结果或已处理的查询故障返回「查询失败：……」及原因；空参数返回「缺少参数 keyword。」。
- 文本会标注数据来源，但不能保证模型一定原样保留。可在提问或人格提示中要求「保留评分来源与分制，不要补造缺失数据」。

### 作品查询：`vn_atelier_search_vn`

按作品名称查询，适合「这是什么游戏」「什么时候发售」「谁制作的」。

```json
{"keyword": "CLANNAD"}
```

启用 Bangumi 时优先返回其游戏资料，包括可取得的评分、评价人数、排名、发售日、原名、平台、开发方与条目链接。
Bangumi 没有结果或查询失败时，改查 VNDB；关闭「启用 Bangumi」时直接查 VNDB。

VNDB 结果可包含多语言标题、别名、评分、评价人数、游玩时长、制作者、发售日与平台；如设置允许，还会尝试关联 Bangumi。
**并非每次都返回两个来源；此工具不提供作品简介。** 要精确指定 Bangumi 条目，请使用下一个工具；VNDB ID 精确查询请用聊天指令 `工房 ID v17`。

### Bangumi 查询：`vn_atelier_search_bangumi`

明确读取 Bangumi 游戏资料，不会用同名动画评分替代，也不会失败后改用 VNDB。

`keyword` 可以是游戏名称、数字 ID 或条目链接，参数值均为字符串：

```json
{"keyword": "CLANNAD"}
```

```json
{"keyword": "13"}
```

```json
{"keyword": "https://bgm.tv/subject/13"}
```

按 ID 或链接可精确读取游戏条目；关键词搜索可能返回多个候选。
可返回评分（10 分制）、评价人数、游戏排名、发售日、原名、平台、开发和发行信息、剧本、原画、音乐、标签、收藏统计及条目链接。
搜索结果中的字段可能少于精确条目查询；文字还受总长度限制。

**此工具不返回完整简介、1–10 分投票分布或图片卡片。** 需要完整的评分档案卡时，请发送 `工房 BGM <名称 / ID / 链接>`。

### 角色查询：`vn_atelier_search_character`

在 VNDB 中按角色名检索：

```json
{"keyword": "Nagisa Furukawa"}
```

可返回角色名、VNDB ID、别称、生日和出场作品；额外信息受「角色卡设置 → 角色卡附加信息」控制，例如血型、身高体重和性别。
含剧透的字段请谨慎开启。中译名是否能命中取决于 VNDB 的收录与别名，可尝试日文原名或罗马音。

### 厂商查询：`vn_atelier_search_producer`

在 VNDB 中按会社或社团名检索：

```json
{"keyword": "Key"}
```

可返回名称、VNDB ID、别称、语言、类型及代表作。每个厂商最多列出 6 部代表作，还受原查询数量设置和总文字长度限制；不是该会社作品的完整清单。

## 数据、权限与限制

- **仅查询游戏资料**：Bangumi 的游戏分类不全是 Galgame，不能将其作为只含视觉小说的数据库。角色和厂商工具使用 VNDB。
- **数据来自第三方**：Bangumi 查询可能命中缓存，默认缓存 6 小时；不是实时评分播报。公开资料通常无需 Bangumi 令牌，受限条目还取决于账号权限和内容设置。
- **成人内容受设置限制**：默认关闭「允许 R18 内容」。即使填写令牌，也不保证所有受限条目可读；第三方标记可能不完整。
- **没有用户账户写入功能**：不会修改 Bangumi 账户收藏，也不会代替用户加入本插件收藏、订阅推送、下载资源或执行服务器操作。
- **不支持额外操作**：评分榜、随机推荐、识图、收藏和推送管理没有对应的 LLM 工具。请使用[聊天指令](usage.md)。
- **有上下文与网络开销**：工具描述和返回文字会占模型上下文，实际查询还会访问数据源。无需 AI 查询时可保持关闭。
- **不是完整资料接口**：不要把最多 3 条、可能截断的检索结果当成完整数据库或全量排行，也不要将 Bangumi 10 分制与 VNDB 100 分制直接混算。见[评分说明](data-sources.md)。

## 模型没有调用怎么办

按以下顺序检查：

1. **开关是否生效**：保存后有没有重载 Gal工房？日志是否出现「已注册 4 个 LLM 工具」或注册失败提示？
2. **工具是否可见**：在 AstrBot 工具管理中查找 `vn_atelier_` 开头的工具，确认未被禁用；若当前人格或会话筛选工具，确认这四个工具在允许范围内。
3. **模型是否支持**：当前模型与接入渠道必须支持工具调用；仅能生成文字的模型无法直接使用。
4. **是否进入聊天流程**：按平时的方式唤醒机器人，并明确说「请用工具查询」。模型直接凭记忆回答，不代表实际查询成功。
5. **数据源是否可用**：用 `工房 BGM CLANNAD` 或 `工房 角色 Nagisa` 测试同一来源。指令也失败时，先按[常见问题](faq.md)排查网络和配置。
6. **是否期望发卡片**：工具只返回文字给模型，聊天指令才负责生成图片。模型文字回复不是卡片渲染故障。

需要稳定且明确的查询结果时，优先使用 `工房` 指令；工具是否被模型选中，不由插件单独决定。
